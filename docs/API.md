# API

Базовый URL в Docker: `http://localhost:8000`. Веб-кабинет доступен на `/`,
Swagger UI — на `/docs`. При локальном запуске самого API без Nginx стандартный адрес
ASP.NET Core — `http://localhost:5000`.

Интерактивная схема ASP.NET Core доступна в Swagger UI по `/docs`. Ниже —
короткая интеграционная инструкция.

## Аутентификация

Все методы, кроме регистрации и health-check, принимают один из заголовков:

```http
X-API-Key: rb_live_...
```

или:

```http
Authorization: Bearer rb_live_...
```

Административное пополнение использует отдельный `X-Admin-Token` из `.env`.

## Методы

### `POST /v1/accounts/register`

Создаёт организацию, начисляет ей 1000 ₽ и возвращает первый API-ключ.

```json
{
  "name": "ООО Ромашка",
  "email": "api@example.ru"
}
```

### `POST /v1/remove-background`

Принимает `multipart/form-data`, поле `image`. Запрос должен содержать ровно один файл.
Поддерживаются реальные (а не только заявленные в `Content-Type`) JPEG, PNG и WebP
до 15 MiB, до 10 000 пикселей по каждой стороне и до 40 млн пикселей всего.

Сервер сохраняет задание и сразу отвечает `202 Accepted`. Заголовок `Location` указывает
на статус, а тело содержит идентификатор и URL результата:

```json
{
  "jobId": "5e6c...",
  "status": "queued",
  "statusUrl": "/v1/jobs/5e6c...",
  "resultUrl": "/v1/jobs/5e6c.../result"
}
```

HTTP-соединение загрузки после этого не связано с инференсом. При переполненной очереди
сервер отвечает `429`; безопасно повторять только запрос, получивший этот ответ.

### `GET /v1/jobs/{job_id}`

Возвращает `queued`, `processing`, `success` или `failed`, число попыток и отдельные
метрики задания: ожидание очереди, время обработки, CPU time, пиковый working set,
размеры, цену и confidence-оценку качества маски. Таймауты и аварийные ошибки worker
повторяются до двух раз (всего не более трёх попыток). Незавершённые задания после
рестарта сервера возвращаются в очередь.

`qualityScore` — доля пикселей маски с уверенностью `≤ 0.1` или `≥ 0.9`. Это полезная
автоматическая эксплуатационная метрика, но не замена IoU/F-score на размеченной
контрольной выборке. `cpuTimeMs` и `peakRamBytes` измеряют процесс API в интервале
задания; при параллельной обработке они включают нагрузку соседних заданий.

### `GET /v1/jobs/{job_id}/result`

Для задания со статусом `success` возвращает итоговый `image/png`. Пока результат не
готов или задание завершилось ошибкой, возвращается `409`.

### `GET /v1/metrics`

Возвращает за всё время аккаунта успешность, p50/p95 времени обработки, максимальную
пиковую RAM и среднюю confidence-оценку качества маски.

### `GET /v1/balance`

Возвращает остаток, успешный объём текущего месяца, цену следующей обработки и все
тарифные ступени.

### `GET /v1/usage?limit=50&offset=0`

Возвращает агрегаты и журнал обработок. Неуспешные операции имеют цену `0.00`.

### `GET /v1/api-keys`

Возвращает ключи без секретной части: имя, префикс, время создания/использования и
отзыва.

### `POST /v1/api-keys`

```json
{"name": "mobile-app"}
```

Секрет нового ключа возвращается только один раз.

### `DELETE /v1/api-keys/{key_id}`

Безвозвратно отзывает ключ. История использования сохраняется.

### `POST /v1/admin/accounts/{account_id}/top-up`

Временная замена эквайрингу для пилота. Требует `X-Admin-Token`.

```json
{
  "amount_rub": "2000.00",
  "description": "Оплата по счёту №42"
}
```

## Ошибки

Ошибки возвращаются единообразно:

```json
{
  "error": {
    "code": "insufficient_funds",
    "message": "Недостаточно средств на балансе",
    "request_id": "1b8d..."
  }
}
```

Основные статусы: `401` — ключ, `402` — баланс, `409` — результат ещё не готов,
`413` — размер/разрешение, `415` — формат или несовпадение реального формата с
`Content-Type`, `422` — повреждённое изображение, `429` — очередь занята. Для временных
состояний сервер возвращает `Retry-After`.
